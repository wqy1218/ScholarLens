# ScholarLens 原理与流程

本文说明 ScholarLens 的架构、数据模型与关键流程，面向想理解实现或二次开发的人。
面向使用者的安装与操作见 [使用说明](使用说明.md)。

---

## 1. 定位

ScholarLens 是一个本地运行的、以**研究领域**为基本组织单元的论文阅读工作台。

面向多领域并行研究，解决三个问题：

1. **知识隔离**：同一篇论文可以同时属于多个领域，领域上下文、笔记与问答按领域组织；
2. **上下文恢复**：切换领域时恢复上次的阅读位置、未决问题与待复核引用；
3. **可控的跨领域**：概念映射、引用图与跨领域建议是显式操作，不污染领域内检索。

## 2. 总体架构

```
┌──────────────────────────── Electron 主进程 (app/main.js) ────────────────────────────┐
│  单实例锁 · 托盘 · 选择空闲端口 · 启动 Python 后端 · 外链独立沙箱窗口            │
└───────────────┬───────────────────────────────────────────────────────────────────────┘
                │ http://127.0.0.1:<port>
┌───────────────▼──────────────────────────────┐   ┌──────────────────────────────────┐
│ 渲染层 (app/renderer)                        │   │ 后端 (server, FastAPI)           │
│ 原生 JS 单页 · PDF.js · 三栏工作台           │◄──┤ /papers /domains /qa /events ... │
│ 不做业务持久化，所有状态经 REST/SSE 读写      │   │ 串行解析 worker · SSE 推送       │
└──────────────────────────────────────────────┘   └───────────────┬──────────────────┘
                                                                   │
                                             ┌─────────────────────▼──────────────────┐
                                             │ SQLite (WAL) + FTS5 + 向量 BLOB        │
                                             │ + 本地嵌入模型 bge-small-en-v1.5       │
                                             │ + 用户配置的大模型 API（可选）          │
                                             └────────────────────────────────────────┘
```

- **壳与界面**：Electron + 原生 JS，不引入前端框架；`contextIsolation` 开启，preload 只暴露
  选文件、后端状态、外链三个能力。
- **后端**：FastAPI 单进程；解析任务进入串行 worker；`/events` 用 SSE 把进度推给前端。
- **存储**：SQLite（WAL）保存论文、领域、引用、笔记、问答、摘要缓存；FTS5 做全文检索；
  chunk 向量以 BLOB 存储在 `chunks.vec`，查询时在内存中做余弦。
- **离线**：嵌入模型随包分发（`models/hf`，`HF_HUB_OFFLINE=1`），导入、解析、归属、检索、
  图谱不需要网络；只有 arXiv 下载与用户主动调用的大模型需要联网。

## 3. 数据模型

核心原则：**关系写进表，约束写进 schema，缓存列必须有唯一写入口。**

| 实体 | 作用 | 关键约束 |
|---|---|---|
| `papers` | 论文全局身份 | `arxiv_id`/`file_path` 唯一；`sha1`、`doi_key` 部分唯一；软删除 `deleted_at` |
| `paper_domain_links` | 论文↔领域，唯一归属事实 | `UNIQUE(paper_id, domain_id)`；`is_primary=1` 每篇至多一条 |
| `chunks` | 解析后的正文分块 | `UNIQUE(paper_id,start_char,end_char)`；FTS5 触发器同步 |
| `citations` | 论文→论文/外部文献的引用边 | 来源/目标 DOI/标题唯一；`status=resolved/unresolved/external/rejected` |
| `anchors` | 高亮/笔记的统一位置 | `(paper_id,page,quote_hash,char_start,end)` 唯一 |
| `interactions` | 高亮、笔记、问答记录 | `type` 区分；`anchor_id` 指锚点；`domains_json` 记录跨领域来源；`importance` 标记重要问答 |
| `concepts` / `concept_definitions` / `concept_mappings` | 概念、按领域定义、跨领域映射 | 映射 `(concept, domain_a, domain_b)` 唯一且 `a<b` |
| `summaries` | 摘要缓存 | 键 `(paper, granularity, research_goal, parse_version)` |
| `questions` / `review_items` | 未决问题、待复核引用 | 状态机 `open/resolved/dismissed`、`pending/confirmed/rejected` |
| `domain_config` / `operation_log` / `domain_snapshots` | 偏好、审计、只读快照 | 快照记录 `last_seq`，恢复需显式复制 |
| `qa_sessions` | 问答线程 | `paper_id IS NULL` 表示领域级；`domain_ids_json` 记录涉及领域 |

`papers.domain_id` 只是**主领域缓存**，由 `set_paper_domain()` 统一维护（`upsert_paper` 在创建/更新身份时同步该缓存）；
读取领域论文、检索、知识视图、图谱都以 `paper_domain_links` 为准。

## 4. 启动流程

1. Electron 取得单实例锁，读取数据目录下的 `backend.lock`，清理上次残留的后端进程；
2. 在 21800–21849 选空闲端口，启动 `python -m uvicorn server.api:app`；
3. 轮询 `/health` 直到就绪（最长 60 秒），失败则弹窗并清理；
4. 创建主窗口，加载 `http://127.0.0.1:<port>/ui/index.html`（HTTP 而非 file://，
   否则 PDF.js 的 worker 无法启动）；
5. 前端启动屏障依次拉取：本地引擎 → 领域 → 概览 → 问答历史；每步失败只影响自己；
6. 后端启动线程做派生状态自检：数值配置、FTS 重建、领域质心重建。
   数据完整性由 `GET /health/integrity` 按需检查，不在启动路径上。

**数据目录**：后端以 `SCHOLARLENS_DATA_DIR` 为唯一数据根（数据库、PDF、缓存、锁文件都在这里）。
打包版由主进程指向 `%APPDATA%\ScholarLens\data`；portable 版指向 exe 同级的 `data\`；
源码运行时是仓库的 `data\`。安装目录只存放程序本身；数据库、PDF、缓存与锁文件都写在数据目录，Python 不写字节码。

关闭窗口默认询问「最小化到托盘 / 彻底退出」（可记住选择）；退出走托盘菜单，先杀后端进程树再清锁。

## 5. 导入与解析

```
arXiv ID/URL ─┐
本地 PDF ─────┼─► 去重（arxiv_id / file_path / sha1 / DOI）
关键词批量 ───┘        │
                       ▼
              复制 PDF 到 data/papers（原子 rename）
                       │
                       ▼
        PyMuPDF 抽取：分块、页码、章节、图表、参考文献
                       │
       ┌───────────────┼────────────────┬──────────────────┐
       ▼               ▼                ▼                  ▼
  写入 chunks    生成 chunk 向量    领域归属            引用解析
  + FTS 索引     （bge-small）    质心余弦 + 离散度     标题/DOI 匹配
                                  超阈值→新建/归入      未匹配→external
                       │
                       ▼
        五段摘要（逐段生成、evidence 逐字校验，写 summaries）
                       │
                       ▼
        领域术语表（glossary → concepts/definitions）
```

- 解析是**串行队列**：一篇失败不会阻塞后续；`parse_status` 为
  `queued/parsing/done/failed`，失败可重试，排队/解析中可取消。
- **扫描页 OCR**：某页可提取文字少于阈值时，渲染成图片交给视觉模型转写（最多 12 页），
  结果并入正文/分块；没有 Key 或调用失败不影响整篇解析，结果写 `papers.ocr_status`。
- `parse_version` 在重新解析时递增，用于让旧摘要与锚点自然失效。
- 导入时选择领域 = 人工归属优先，写 `lock_domain`；否则按质心相似度自动归属。
- 重复导入同一 arXiv ID 返回 `duplicate` 并跳过，不覆盖摘要/向量/锁定状态，也不重新解析；
  若请求指定了领域，会为该论文补建兼属链接（不改变已有主领域）。
- 同一篇论文在多个领域出现时只保留一个 `paper_id`，通过 links 表达兼属。
- 双栏阅读顺序：全宽标题/摘要/表格作为"屏障"，屏障之间按左栏→右栏排序；图片按阅读序号插入。
- 文本清洗：行尾连字符去断词、段内换行折叠、`ﬁ/ﬂ/ﬀ/ﬃ/ﬄ` 归一化、软连字符/零宽字符清理；
  这些处理直接影响 FTS 命中、向量质量与 evidence 定位。
- 网页链接：优先 PDF Link 注释；没有注释时对整页文本节点拼接后匹配 `http(s)`，
  因此跨行/跨栏拆开的 URL 仍能还原；点击热点用页面坐标兜底。
- 页内跳转：解析 PDF 目的地 `XYZ`（top 在索引 3）与 `FitH/FitBH`（top 在索引 2），
  并用 viewport 变换换算滚动位置，双栏目标不会落到页首。

## 6. 检索与问答

**检索**：`FTS5 BM25 + chunk 向量余弦 → RRF(k=60) 融合 top-8`。

- 范围是硬过滤：单篇问答只取该论文 chunk；领域问答按 `paper_domain_links` 过滤；
  指定论文子集时再按 `paper_id IN (...)` 收窄。
- **范围推断**：用户没选范围时，后端用问题向量分别比"本文 chunk / 各领域质心"，
  给出 `paper / domain / domains / all` 与置信度；前端在回答前显示可点击的「范围」标签，
  点开即可改成别的范围并重问（推断结果不写回会话）。
- **领域权重**：跨领域检索按 `domains.weight`（主攻 1.0 / 交叉 0.6 / 了解 0.3）加权排序；
  同时先按问题向量选出**主领域**，主领域按完整深度检索，其他领域按广度检索。
- **领域超时**：多领域检索逐域执行，超时或报错的领域进入"证据不完整"清单，
  回答里标注哪些领域未取得结果。
- **来源**：材料由论文片段与用户批注组成，引用 `[n]` 会标注来源（论文 / 笔记）；
  不联网检索，材料只来自库内。
- 检索为空且最高向量相似度低于阈值时直接回答"材料中未找到"，不让模型编造。
- 回答要求逐条标注 `[n]`，后端校验编号是否落在本次材料内（越界编号会随回答下发并在界面上标红）；材料不足时明确说明。
- **概念对照**：问题命中已建概念且有按领域定义时，把"某术语在各领域的不同定义/映射类型"
  注入提示词，让回答按来源领域分别说明（概念映射不只在界面里）；标记为"含义相同"的术语
  还会作为跨领域检索的连接点加入查询。

**问答线程**：`qa_sessions` 保存会话（可按论文/领域/指定论文子集），
`interactions(type=qa)` 保存每轮问题、回答、引用、证据完整性、涉及领域与 `importance`；多轮历史取最近 3 轮注入。
标记为重要的一轮会在 `interactions(type=note)` 生成一条带 `qa_turn_id` 的镜像笔记，
和普通批注一起进入论文笔记页与领域笔记汇总；取消标记或撤回该轮时镜像一并删除。

## 7. 阅读、标注与翻译

- PDF 用 PDF.js 渲染 canvas + text layer；text layer 文字透明，选中只显示半透明背景，
  不改变正文颜色（否则会把透明文本层"显影"）。
- 划选 → 浮层菜单 → 翻译 / 解释 / 高亮 / 批注；翻译按句缓存
  （`paper_id+sentence+mode`），部分重叠的选区可复用。
- 高亮与笔记共用 `anchors`（页码、原文、字符偏移、矩形、解析版本）；
  自动高亮由用户触发，重跑时"先收集后一次事务替换"，失败保留旧集。
- 高亮页可按三类筛选，三类颜色写入 `domain_config.color_scheme_json`，
  以 CSS 变量应用到 PDF 文本层；切换领域时恢复该领域的配色。
- 「结构」把章节大纲、图表、表格与算法做成索引；正文里的 Fig./Table/Algorithm
  编号可点击定位到对应条目，图表条目会在页面上高亮其区域。
- 批注可打标签（问题/方法/结论/局限/想法，存 `interactions.tags_json`），
  论文内与领域汇总都支持按标签筛选。
- 外链：PDF 的 Link 注释与正文中可见的 `http(s)` 都会生成点击区域；
  点击后由主进程打开一个**独立的沙箱浏览器窗口**（`sandbox/contextIsolation`，
  无 Node 权限），不依赖系统默认浏览器，也不影响阅读窗口。

## 8. 领域切换、快照与审计

- 阅读位置与进度按 `(paper, domain)` 存在 link 上；切换领域恢复该领域的阅读位置。
- 领域可设父领域（树形，拖拽建立，后端拒绝环）；「拆」把选中论文拆成新领域，
  论文列表可把论文拖到领域目标上调整主领域；合并会把子领域重挂到目标领域，并拒绝合并进自己的后代。
- 领域概览展示子主题、未决问题与待复核引用；同一概念在其他领域有定义时，
  论文摘要页与领域概览会给出跨领域提示，可在「知」中对照定义。
- 所有领域/论文的移动、合并、删除、快照、导出、权重调整写入 `operation_log`（单调 seq）。
- `domain_snapshots` 是只读归档：记录当时的链接、未决问题、待复核引用与 `last_seq`；
  不直接覆盖实时表。

## 9. 跨领域

- **概念映射**：`concept_mappings` 记录同一概念在两个领域是 same/different/related；
  论文打开与领域概览会主动提示其他领域的同名定义，问答按当前领域取定义并注入对照；
  same 映射还会作为跨领域检索的连接点。
- **引用图**：`citations` 提供论文→论文边；图谱把主归属、弱关联、引用边分层绘制。
- **跨领域建议**：`cross_domain_suggestions` 用 `fingerprint` 去重，`snooze_until` 支持稍后提醒，
  忽略后不会因重新生成而重复推送。

## 10. 可靠性、安全与性能

- **完整性**：新表启用外键；旧表用显式级联（`delete_paper`）与领域触发器；
  `GET /health/integrity` 检查主链接唯一、孤儿行、重复 DOI/sha1。
- **安全**：后端只监听 `127.0.0.1`，CORS 限定 loopback；PDF 只从 `data/papers` 提供；
  外链只允许 `http(s)` 并由主进程校验；API Key 在后端接口返回时脱敏。
- **性能**：SSE 合并刷新；首页跟随光只在可见且指针移动时运行；
  摘要逐段生成并缓存，翻译按句缓存；问答按轮次检索并保留会话上下文，不使用响应缓存。
  模型响应缓存在数据目录的 `llm_cache.db`（随 `SCHOLARLENS_DATA_DIR` 走，安装目录保持只读）。

## 11. 目录结构

```
app/                 Electron 主进程、preload、渲染层（index.html / renderer.js / style.css）
server/              FastAPI 后端：api/store/assign/retrieval/llm/pdfio/ocr/summarize/translate...
scripts/             运行、迁移、自检脚本（check_integrity / test_schema / test_api / smoke_domains）
docs/                使用说明、原理与流程
assets/              应用图标
tools/               图标几何预览（开发用）
data/                运行期数据（数据库、PDF、缓存），不随源码分发
models/              本地嵌入模型（打包时随安装包）
python-runtime/      随包 Python 运行时（打包时随安装包）
```
